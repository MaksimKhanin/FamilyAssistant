# Roadmap: живой, универсальный, подстраивающийся ассистент

Этот документ — итог аудита поведения агента (август 2026) и план его развития
по трём направлениям: **живость** (звучит как человек, а не как система),
**универсальность** (меньше зашитого, больше растущего), **подстройка под
человека** (помнит, учится, предугадывает). Плюс новые фичи.

Работа разбита на тикеты — карта и дочерние issues в GitHub (метки
`wayfinder:map` / `wayfinder:task`). Каждая фаза оставляет приложение
шипуемым.

## Диагноз

Агент честный и дисциплинированный, но механический по краям и статичный
в середине:

1. **Персона живёт только в основном цикле.** `character_block` едет в каждый
   ход `_respond`, но служебные реплики минуют её полностью: `OFFLINE_REPLY`,
   `UNBACKED_REPLY`, «Похоже, я закопался в подсчётах…», строки
   `_fallback_answer` (всё — `app/agent/runtime.py`), «Напоминаю: …» и
   открытия сводок «Доброе утро.» (`app/scheduler.py`), статичные `SUGGESTIONS`
   (`app/web/routes_chat.py`). Ровно этот класс бага уже чинился один раз для
   подтверждений — паттерн `_phrase()` / `_APPROVE_HINT` в runtime.py
   существует (#78), но применён только там.
2. **Промпт-налог фиксированный.** `MEAL_RULES` (~50 строк) едет каждому
   с включённым питанием на каждый вопрос, включая «что было ночью дома?».
   Механизм скиллов из `docs/skills.md` §7 описан, но не реализован.
3. **Память шириной в 16 сообщений и поиском по подстроке.** `recall` — чистый
   ILIKE (`search_entries` в `app/modules/memory/knowledge.py`): «грибы» не
   найдут «шампиньоны». История за окном `HISTORY_LIMIT` исчезает,
   `person_facts` берёт записи по свежести, а не по релевантности. Модуль
   «Подход» — единственный механизм автоматической подстройки — выключен по
   умолчанию (миграция 0015), а его digest затирает рукописную памятку.
4. **Анти-фабрикация привязана к русской морфологии** (`_DONE_CLAIM` и соседи
   в runtime.py) и при втором срабатывании выбрасывает весь ответ, включая
   его корректную часть.
5. **Проактивность хрупкая.** `_due` в scheduler.py требует точного попадания
   в минуту: проспал тик — сводки нет до завтра. Напоминания только разовые,
   с абсолютным временем.

## Track A — «Живость»

### A1. Единый «голосовой» хелпер: служебные реплики через персону — S/M

Вынести `_phrase()` из runtime.py в новый `app/agent/voice.py`:
`speak(subject, hint, fact="", llm=None, fallback="")` — системный промпт
`WHO + character_block + TONE`, при `LLMUnavailable` возврат `fallback`
(текущая каноническая строка). Применить к `UNBACKED_REPLY`, «закопался
в подсчётах», строкам `_fallback_answer`.

`OFFLINE_REPLY` так не переозвучить — модель в этот момент лежит. Вместо
этого при сохранении характера (`set_character`, экран профиля) один раз
генерировать и кешировать 2–3 «офлайн-фразы» (поле у пользователя, миграция;
можно отложить) и ротировать их.

- Файлы: новый `app/agent/voice.py`, `app/agent/runtime.py`.
- Testkit: `honesty.yaml`, `failures.yaml`, `agent-limits.yaml` пинят точные
  строки. Контракт совместимости: скриптованная модель директора без реплики
  для voice-вызова → путь `LLMUnavailable` → fallback = старая строка,
  сценарии остаются зелёными. Зафиксировать тестом.

### A2. Сводки и напоминания голосом персоны — M

В `run_jobs` / `run_reminders` после сборки фактов (`_digest_text` не
трогаем — факты собирают инструменты) один вызов `voice.speak` с hint'ом
в духе `_APPROVE_HINT`: «Перескажи человеку эту сводку в своей манере,
строго по фактам ниже, ничего не добавляя. Сейчас {утро/вечер/конец недели},
{дата}». Fallback — текущий формат с «Доброе утро.» / «Напоминаю:».
Гарантия честности сохраняется: числа посчитаны кодом, модель только
формулирует — тот же принцип, что `BOARD_STATS_SYSTEM`.

- Файлы: `app/scheduler.py`, `app/agent/voice.py`.
- Цена: +1 вызов ROUTINE на сводку/напоминание — единицы в день на человека.
- Testkit: `reminders.yaml`, `board-stats.yaml`, `reminder-via-chat.yaml` —
  тот же fallback-контракт, что в A1.

### A3. Догоняющие сводки — S

`_due` требует точного совпадения минуты. Изменить на «время наступило
сегодня И `last_run_at` раньше сегодняшнего времени срабатывания», с окном
навёрстывания ~2 часа. Прямо влияет на ощущение «он стабильно рядом».

- Файлы: `app/scheduler.py` (`_due`). Юнит-тест на навёрстывание.

### A4. Follow-up: возвращение к вчерашним темам — M

При утренней сводке, если у человека включён «Подход», брать последнюю
запись доски «Итоги разговоров» и передавать её в тот же voice-вызов A2
как опциональный материал: «если уместно, одной фразой вернись к вчерашней
теме». Максимум одна фраза, отключается правилом (`set_rule` уже умеет).
Ноль новых LLM-вызовов — едет в вызов A2. Зависит от C1.

- Файлы: `app/scheduler.py`, хелпер в `app/modules/relationship/service.py`.

### A5. Контекст времени суток в основном промпте — S

`system_prompt` уже содержит «Сейчас: …». Добавить одну строку-ориентир
(здороваться по времени суток, поздним вечером — короче) в нейтральной
форме. Это не манера (ADR-0006: манера — в характере), а факт контекста.
Промпт-налог: +1–2 строки.

- Файлы: `app/agent/prompts.py`.

## Track B — «Универсальность»

### B1. Механизм скиллов `load_skill` — M

Реализовать рецепт `docs/skills.md` §7 дословно: каталог `skills/` в корне,
парсинг фронтматтеров при старте, инструмент `load_skill(name)` через
`@tool(read_only=True)`, enum имён в схеме, фильтр по модулям человека,
строка в `TOOLS_RULES`.

Первый переезжающий контент — хвост `MEAL_RULES` про книгу рецептов
(~20 строк) → скилл `recipe-book`. Ядро `MEAL_RULES` (запись, уточнение,
цифры) остаётся в промпте: на малой модели нельзя ставить корректность
`log_meal` в зависимость от выбора скилла. Экономия ~15–20 строк промпта
на каждый ход; главное — канал для роста без роста налога.

- Файлы: новый `app/agent/skills.py`, `skills/recipe-book/SKILL.md`,
  `app/agent/prompts.py`, `docs/agent.md`.
- Testkit: `recipe-book.yaml` — заскриптовать вызов `load_skill` в
  директоре; метрика выбора по «списку настоящих фраз» (`docs/skills.md` §8).
- Риск: качество выбора скилла на локальной 8B-модели — поэтому начинаем
  с одного скилла и меряем.

### B2. Tool-call-нативная история — осознанный отказ (ADR)

Обоснование трейла в runtime.py остаётся верным: скользящее окно режет пару
«assistant+tool_calls / tool», на которую падает половина OpenAI-совместимых
серверов; резать по границам групп ходов — L-размерный рефактор
`load_history` с матрицей совместимости провайдеров ради выгоды, которую
трейл уже покрывает. Дешёвая альтернатива: поднять `TRAIL_SUMMARY_LIMIT`
со 120 до ~200 и возить аргументы вызова целиком. Зафиксировать короткой
ADR («история — реплики плюс служебные записи, не tool_calls»), чтобы
вопрос не переоткрывался. Туда же — абзац об i18n (см. B5).

### B3. Настраиваемый MAX_STEPS и честное переполнение — S

`AGENT_MAX_STEPS` в config (default 4). Упёрся в лимит, но инструменты
на последних шагах отработали — не канонический «закопался», а честный
persona-ответ через A1 с фактами из трейсов («вот что успел: …»).

- Файлы: `app/agent/runtime.py`, `app/core/config.py`.
- Testkit: обновить `agent-limits.yaml`.

### B4. Анти-фабрикация как модуль с подключаемыми детекторами — M

Извлечь `_DONE_CLAIM` / `_NOT_A_CLAIM` / `_claims_done` / `_unbacked` /
`_own_words` в `app/agent/honesty.py` с интерфейсом «детектор отчёта
о сделанном». Русский regex остаётся детектором по умолчанию (быстрый,
бесплатный, проверенный прогонами #74/#81/#82). Добавить опциональный
LLM-judge второй ступени (env `HONESTY_JUDGE=1`): regex сработал → один
`json_completion` «утверждает ли реплика о выполненном изменении данных?»
→ глушим ответ только при подтверждении. Снижает цену ложного
срабатывания (сейчас — выброшенный живой ответ) и даёт языконезависимый
путь на будущее. Замена `UNBACKED_REPLY` — через A1.

- Файлы: новый `app/agent/honesty.py`, `app/agent/runtime.py`.
- Testkit: `honesty.yaml` с выключенным judge (default) + сценарий
  с включённым.

### B5. i18n — вне скоупа

Русский зашит в промпты, ключевики стаба, канонические строки, 35
YAML-сценариев и сами доски. Польза для русскоязычной семьи нулевая,
стоимость — XL. Делаем только языконезависимый детектор (B4), решение
фиксируем абзацем в ADR из B2.

## Track C — «Подстройка под человека»

### C1. «Подход» включён по умолчанию для новых участников — S + ADR + миграция

Новая ADR: пересмотр решения миграции 0015. Default=True для новых
участников (онбординг показывает тумблер явно), существующих не трогаем —
их opt-out закреплён сознательно, молча включать наблюдение за стилем
общения нельзя.

- Файлы: `app/scheduler.py` (`enabled_user_ids(..., default=...)`),
  `app/core/access.py`, `app/web/routes_onboarding.py`, миграция, ADR.
- Попутно: номера ADR 0004 и 0012 задублированы — перенумеровать.

### C2. Digest «Подхода» дополняет, а не затирает памятку — S

`_apply` в `app/modules/relationship/service.py` пишет digest через
`set_memo(..., "relationship", ...)` — рукописное погибает. Решение без
доверия модели: хранить авто-digest под отдельным ключом
(`relationship.auto`), а `instructions.for_prompt` при включённом модуле
добавляет вторую пару («Подход (заметки ассистента)»). Экран профиля
показывает авто-часть read-only.

- Файлы: `app/modules/relationship/service.py`, `app/core/instructions.py`,
  шаблон профиля.

### C3. Семантический recall — L, самый рискованный пункт

Таблица `board_entry_embeddings (entry_id, model, vector BLOB, updated_at)`:
float32, упакованный `struct`-ом, косинус в Python по кандидатам. Корпус
семьи мал по построению (капы 50/20 записей на системных досках, сотни —
максимум тысячи записей всего), brute-force — миллисекунды. Работает
одинаково на SQLite и Postgres, ноль нативных расширений и двойных путей.
sqlite-vec/pgvector отклоняем осознанно — записать в ADR с порогом
пересмотра («если записей у семьи > ~10k»).

Эмбеддер: OpenAI-совместимый `/embeddings` тем же голым-HTTP стилем, что
`speech.synthesize` — новый `app/core/embeddings.py`, env
`EMBED_BASE_URL/EMBED_MODEL/EMBED_API_KEY`. Не задан — recall остаётся
чистым ILIKE (стаб и офлайн живут как жили). Гибрид: ILIKE-совпадения
первыми, затем top-k по косинусу, общий limit 8. Индексация: best-effort
при создании/правке записи + догоняющий backfill-джоб в `tick()` батчами.

- Файлы: `app/core/embeddings.py` (новый),
  `app/modules/memory/knowledge.py` (`search_entries`, `person_facts` —
  тоже на релевантность), модели + миграция, `app/scheduler.py`,
  `app/core/config.py`.
- Testkit: сценарии гоняются без `EMBED_*` — поведение бит-в-бит прежнее;
  юнит-тесты на косинус/упаковку.

### C4. Память за окном 16 сообщений — M

Не заводить отдельный summarizer: разбор «Подхода» уже пишет по одному
итогу на каждый кусок разговора в доску «Итоги разговоров». Инжектить
последние 2–3 итога системным блоком «О чём вы говорили раньше» в
`system_prompt` (~3–4 строки налога). Ноль новых LLM-вызовов. Зависит от
C1 (иначе итогов нет); у кого «Подход» выключен — ничего, честно.

- Файлы: `app/agent/runtime.py`, `app/agent/prompts.py`, хелпер в
  `app/modules/memory/knowledge.py`.

### C5. Живые подсказки в чате — S/M

Заменить статичный `SUGGESTIONS` в `app/web/routes_chat.py` функцией без
LLM: подбор из (а) включённых модулей, (б) состояния дня — нет записей еды
к обеду → «Съел…», есть напоминание на сегодня → «Что у меня сегодня?»,
(в) 1–2 самых частых инструментов человека из `action_log` за месяц.
Считается при открытии чата, запросы лёгкие.

## Новые фичи

### F7. Поиск в интернете и комплексный ответ — M (приоритет)

Общий инструмент поверх готового `app/core/websearch.py` (сейчас им
пользуется только `lookup_product` питания):

- Инструмент `search_web` (`read_only`, в схеме модели только при
  настроенном `WEB_SEARCH_PROVIDER`): запрос → заголовок/домен/выдержка
  топ-N результатов в tool-summary. При `SearchUnavailable` — честное
  «поиск не настроен/не отвечает», модель отвечает своими знаниями и
  говорит об этом.
- Комплексный ответ: правило в промпте (позже — скилл через B1): когда
  вопрос про внешний мир или свежие факты — сначала `search_web` (2–3
  запроса в рамках MAX_STEPS), затем связный ответ с названием источников
  («по данным <домен>…»), без выдумывания; оценки — оценками (TONE).
- Размещение: новый лёгкий модуль `web` («Интернет») с per-user флагом
  `ModuleAccess` — админ решает, кому ассистент может ходить наружу (та же
  логика приватности, что у камер). Без своего экрана: инструмент + тумблер.
- Вторая итерация: `open_page(url)` — вытяжка текста страницы для глубокого
  ответа. В первую итерацию не входит: ответ строится по выдержкам, как
  в двухпроходном `lookup.py`.
- Testkit (обязательная часть тикета): (а) вопрос, требующий интернета →
  скриптованный `search_web` (мок результатов на уровне `WebSearchClient`,
  по образцу мока LLM в `app/testkit/director.py`) → в ответе названы
  источники; (б) поиск не настроен → честный ответ без выдуманных ссылок;
  (в) комплексный вопрос → два поисковых вызова → связный ответ.

### F2. Повторяющиеся напоминания — M (приоритет, backlog #8)

`Reminder.recurrence` (nullable: `daily` / `weekly:0-6` / `monthly:1-31`),
после срабатывания вычисляется следующий `remind_at` вместо пометки
отработавшим, `purge_fired` повторяющиеся не трогает, `set_reminder`
получает аргумент, `cancel_reminder` работает как есть. Доставка — через
A2 (голосом персоны).

- Файлы: `app/modules/memory/models.py`, `reminders.py`, `tools.py`,
  `app/scheduler.py`; миграция.
- Testkit: обновить `reminders.yaml` / `reminder-cancel.yaml`, новый
  сценарий на повтор.

### F4. «Ассистент сам предлагает» — M (приоритет)

Еженедельный джоб в `tick()`: один `json_completion` на человека (материал:
сводка `action_log` за неделю, памятки, топ досок, итоги разговоров) →
0–2 предложения («вы каждый вечер записываете шаги руками — поставить
табло?») на доску «Идеи ассистента» + строка в еженедельной сводке.
Жёсткий лимит ≤2/неделю, опт-аут правилом, ничего не делает сам — только
предлагает (уважает автономность). Реюз: `run_tool_directly`,
`add_assistant_entry`, капы досок, bus `AGENT_MESSAGE`. Закрывает и
backlog-пункт «ассистент предлагает уточнения инструкций досок».
Зависит от C1 (материал).

### F3. Список покупок — M/L (приоритет)

Полный прогон module-contract: `app/modules/shopping/` — модель
`shopping_items` (family-scoped), инструменты `add_to_shopping_list` /
`show_shopping_list` / `check_off_item`, экран-чеклист, NavItem. Шов
с питанием: «собери список из плана питания» (читает план). Коннектор
`grocery` из каталога становится осмысленным на будущее.

- Testkit: 2–3 сценария (добавление, семейная видимость, вычёркивание).

### Очередь (без тикетов пока)

- **F1. Голосовой ввод (STT)** — зеркало `speech.py`: `app/core/stt.py`
  через OpenAI-совместимый `/audio/transcriptions`, кнопка-микрофон в чате
  (распознанный текст попадает в поле ввода — человек правит перед
  отправкой).
- **F6. Общесемейная еженедельная сводка** — общие доски + безопасность,
  одно сообщение на всех через bus, голосом персоны каждого получателя;
  никаких чужих личных цифр (принцип ADR-0005).
- **F5. Семейный календарь + первый настоящий коннектор (CalDAV)** —
  сначала модуль (события, add/list/today, строка в утренней сводке),
  затем CalDAV-синк на чтение. Внешний мир (auth, таймзоны, повторы) —
  поэтому последним.

## Фазировка

| Фаза | Состав | Итог для человека |
|---|---|---|
| 1. Голос и пульс | A1, A2, A3, A5, B3, C2, C5 | Ассистент звучит собой везде, сводки не пропадают, подсказки живые |
| 2. Память и знания извне | C1 (+ADR), A4, C4, B4, F2, F7 | Подстройка включена, помнит «вчера», повторные напоминания, отвечает с опорой на интернет |
| 3. Универсальность | B1, C3 (+ `open_page` для F7 при необходимости) | Промпт худеет, recall находит по смыслу |
| 4. Новые поверхности | F4, F3; далее очередь F1, F6, F5 | Ассистент сам предлагает, список покупок |

Каждая фаза шипуема сама по себе.

## Сквозные правила

Любой новый LLM-вызов обязан: (а) деградировать к детерминированному
fallback при `LLMUnavailable`/стабе — это же держит testkit-сценарии
зелёными; (б) писаться в трейс (`app/agent/tracing.py`); (в) идти
с `task=ROUTINE` (ADR-0009). Любая новая строка промпта — с оглядкой на
бюджет малых моделей: фазы 1–2 суммарно добавляют ~5–6 строк, фаза 3
убирает ~15–20.

## Риски

- **C3** — новая инфраструктура; митигация: graceful degradation к ILIKE,
  Python-косинус вместо нативных расширений.
- **B1** — качество выбора скилла на малой модели; митигация: один скилл
  на старте + метрика фраз из `docs/skills.md` §8.
- **C1** — приватность; митигация: default только новым участникам + ADR.
- **F7** — качество источников и соблазн выдумывать ссылки; митигация:
  источники только из tool-summary, testkit-сценарий на «поиск не настроен».
- **F5** — внешние интеграции; поэтому в самом конце очереди.
