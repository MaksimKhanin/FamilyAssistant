# Развёртывание

Две части: сервер (Docker) и домашний воркер рядом с камерами (обычный Python-процесс).

Просто посмотреть, как всё работает, проще без этого: `python run_local.py` поднимет
панель на SQLite с демо-данными и офлайн-агентом (см. README).

## Сервер

```bash
git clone <repo> && cd FamilyAssistant
cp .env.__EXAMPLE__ .env
```

Заполнить `.env`. Секреты обязательны, случайную строку удобно получить так:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

| Переменная | Зачем |
|---|---|
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | первый вход в панель; глава семьи создаётся при первом старте |
| `ADMIN_NAME`, `ADMIN_RELATION`, `FAMILY_NAME` | как его зовут и как называется семья |
| `POSTGRES_PASSWORD` | пароль БД |
| `SESSION_SECRET` | подпись сессионных cookie; поменяется — все выйдут из панели |
| `INGEST_API_KEY` | им домашний воркер представляется серверу |
| `VAPID_*` | ключи для уведомлений, см. ниже |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | модель; без них панель работает, чат — нет |
| `PUBLIC_BASE_URL` | адрес панели снаружи — подставляется в ссылки-приглашения и уведомления |
| `COOKIE_SECURE` | `true` только за HTTPS |

Ключи для уведомлений генерируются один раз и кладутся в `.env`:

```bash
docker compose run --rm web python -m scripts.vapid_keys
```

Менять их потом нельзя: все подписки устройств станут недействительными, и семье
придётся заново разрешать уведомления в профиле.

Запуск:

```bash
docker compose up -d --build
```

Поднимутся `web` (панель + уведомления + ingest), `scheduler`, `db` и `redis`.
Проверить: `curl localhost:5000/healthz`.

### Учётные записи

Глава семьи заводится автоматически при первом старте — из `ADMIN_*`. Дальше
консоль не нужна: **Настройки → Семья и модули** в панели умеет всё, что требуется
семье из пяти человек.

| Действие | Что происходит |
|---|---|
| Добавить человека | заводится учётка без пароля и выдаётся одноразовая ссылка |
| Выпустить ссылку / сбросить пароль | одна и та же кнопка: старый пароль и старая ссылка перестают работать |
| Отозвать ссылку | неиспользованное приглашение аннулируется, вошедших не трогает |
| Сделать главой / снять роль | вторая пара рук; свою роль сменить нельзя |
| Удалить | человек и все его записи — еда, знания, переписка, подписки на уведомления |
| Модули | тумблер на каждого человека и каждый модуль |

Пароль человек придумывает себе сам по ссылке — администратор его не задаёт и не
видит. Себя удалить или разжаловать нельзя: единственный администратор не должен
уметь запереть себя снаружи.

**Забыли пароль администратора.** `ADMIN_PASSWORD_RESET=true` в `.env`,
`docker compose up -d`, войти — и сразу вернуть `false`. Пароли остальных
сбрасывает глава семьи в панели.

### HTTPS обязателен

Не для галочки: без TLS браузер не даст ни установить приложение на телефон, ни
подписаться на уведомления — service worker работает только на HTTPS (исключение —
`localhost` для разработки). Плюс `COOKIE_SECURE=true` по простому HTTP молча
выбрасывает сессионную куку, и вход «не срабатывает» без всякой ошибки.

Ставьте панель за nginx / Caddy / Traefik с настоящим сертификатом. Caddy делает это
в две строки:

```
assistant.example.com {
    reverse_proxy localhost:5000
}
```

### Установка на телефон

* **Android (Chrome):** открыть панель → «Установить приложение» (или меню →
  «Добавить на главный экран»).
* **iPhone (Safari):** «Поделиться» → «На экран Домой». Это не косметика: до
  установки iOS вообще не отдаёт сайту push-уведомления.

Дальше в «Настройки → Профиль» человек включает уведомления и жмёт «Проверить» —
должно прийти тестовое сообщение.

### Необязательный Telegram

Если мессенджер всё-таки понадобится, у бота есть готовый профиль:

```bash
docker compose --profile telegram up -d
```

Нужен `TELEGRAM_BOT_TOKEN` от [@BotFather](https://t.me/BotFather). Бот подключается
к тому же диалогу и тем же инструментам — это просто ещё один транспорт.

## Домашний рекордер

Живёт в **отдельном репозитории** (YACAID) и ставится **на машине рядом с камерами**:
RTSP по интернету гонять незачем, да и YOLO должен работать там, где кадры и так есть.
Он берёт на себя всё тяжёлое — потоки, движение, детекцию, нарезку и склейку видео, —
а сюда присылает готовые файлы.

```bash
pip install -r requirements-recorder.txt
cp cfg/cfg.yml.__EXAMPLE__ cfg/cfg.yml
cp cfg/cfg.local.yml.__EXAMPLE__ cfg/cfg.local.yml   # сюда — RTSP-логины и ключи
python run_recorder.py
```

В `cfg/cfg.local.yml` (не коммитится) — адреса камер, а также:

```yaml
archive_sync:
  base_url: https://ваш-сервер            # адрес этой панели
  api_key:  <тот же INGEST_API_KEY>
control:
  host: 127.0.0.1                          # 0.0.0.0, если UI нужен с телефона
  token: <тот же CONTROL_API_TOKEN>
```

Веса YOLO и `ffmpeg` нужны на стороне рекордера, серверу они не нужны. Камера
появится в панели сама, после первого присланного файла — заводить её руками не надо.

Свой веб-интерфейс рекордера (по умолчанию `http://127.0.0.1:8090`) показывает
состояние камер, бэклог отправки и позволяет менять настройки — это отдельная
дверь, внутрь домашней сети.

### Как рекордеру достучаться до сервера

Публиковать ingest в интернет необязательно и нежелательно. Варианты, от простого:

* **Приватная сеть** (Tailscale / WireGuard) — рекордер видит сервер по внутреннему
  адресу, наружу не торчит ничего.
* **SSH reverse tunnel** — если сервер снаружи, а дом за NAT.
* **Публичный HTTPS** — тогда обязательно с TLS и длинным `INGEST_API_KEY`.

Обратное направление — пульт. Если задать на сервере `CONTROL_BASE_URL` и
`CONTROL_API_TOKEN`, на карточках камер появятся кнопки «тревога», «снять кадр»,
«записать»; панель просто перешлёт их рекордеру. Адрес пульта должен быть
приватным: за этой дверью управление домом, а не просмотр архива.

### Автозапуск (systemd)

```ini
[Unit]
Description=YACAID recorder
After=network-online.target

[Service]
WorkingDirectory=/opt/YACAIDv2
ExecStart=/opt/YACAIDv2/.venv/bin/python run_recorder.py
Restart=always
RestartSec=10
User=family

[Install]
WantedBy=multi-user.target
```

## Эксплуатация

**Логи.** `docker compose logs -f web scheduler`. Уровень — `LOG_LEVEL`.

**Обновление версии.** Есть готовый сценарий, он проводит по всем шагам и
проверяет результат:

```bash
bash scripts/upgrade.sh
```

Руками это те же четыре команды, и порядок в них важен:

```bash
git pull
docker compose build
docker compose run --rm web alembic upgrade head
docker compose up -d
```

Три ловушки, на которые легко наступить дважды.

**`docker compose up -d` без `--build` не обновляет код.** Исходники запечены в
образ (`COPY app ./app` в Dockerfile), бинд-маунта нет, а compose смотрит на
конфигурацию, а не на файлы рядом. Ничего не изменилось в `docker-compose.yml` —
значит, контейнеры остаются на старом образе, и в выводе стоит `Running` вместо
`Recreated`. Внешне это выглядит как «обновился, но ничего не поменялось»:
`git pull` прошёл, панель отдаёт прежние экраны. Проверять надо не файлы на
диске, а то, что отдаёт сервер: `curl -s localhost:5000/static/style.css | head -3`.

**Базовый образ тянется из Docker Hub, и это не всегда получается.** Сборка
падает на `FROM python:3.11-slim` с `read: connection timed out` — обычно на
IPv6-маршруте до CDN. Лечится зеркалом в `/etc/docker/daemon.json`:

```json
{ "registry-mirrors": ["https://mirror.gcr.io"] }
```

После правки — `sudo systemctl restart docker` и `docker pull python:3.11-slim`
отдельной командой: так видно, помогло ли, не дожидаясь всей сборки. Зеркало —
это кеш того же Docker Hub, образы приезжают те же; сторонние зеркала лучше не
брать, через них едет код, который потом крутится дома. Если и зеркало молчит,
проверьте, дело ли в IPv6: `curl -4` против `curl -6` до
`https://registry-1.docker.io/v2/` (401 — нормальный ответ, связь есть).

**Переменная из `.env` не доезжает до контейнера сама.** Compose читает `.env`
только для подстановки `${...}` в сам `docker-compose.yml`; внутрь контейнера
попадает ровно то, что перечислено в блоке `environment:` у `x-app`. `env_file`
здесь нет намеренно — так видно, чем живёт сервер. Значит, новая настройка
добавляется в два места: в `.env.__EXAMPLE__` (чтобы её нашли) и в
`docker-compose.yml` (чтобы она работала). Забытая строка выглядит не как
ошибка, а как «функция выключена»: приложение честно видит пустое значение и
идёт по запасному пути. Проверять так:

```bash
docker compose exec web env | grep WEB_SEARCH
```

**Схема БД.** Изменения схемы едут пронумерованными миграциями Alembic; при
обновлении версии прогоните их до старта сервисов:

```bash
docker compose run --rm web alembic upgrade head
```

Команда идемпотентна: на уже обновлённой базе она молчит. Baseline-миграция
фиксирует схему, какой её создавал `create_all()`, так что первый прогон на
живой базе тоже безопасен — он лишь помечает её текущей.

Пустую базу по-прежнему разворачивает тот процесс, который поднялся первым: и
`web`, и `scheduler`, и бот вызывают `create_all()` при старте. Но живую базу
`create_all()` не трогает — менять её может только миграция, поэтому прогон
`alembic upgrade head` при обновлении обязателен. Если планировщик сыплет
`relation "scheduled_jobs" does not exist`, значит `web` не поднялся: смотрите
`docker compose ps` и `docker compose logs web`.

**Диск.** Кадры и видео лежат в томе `media`, ротация — по `Camera.retention_days`
(14 дней по умолчанию, общий запасной срок — `MEDIA_RETENTION_DAYS`), делает
`scheduler` ночью в 4:00. Событие в БД переживает свой снимок; записи архива
удаляются целиком вместе с файлом и превью. Видео занимает на порядок больше
снимков — если том растёт быстрее, чем хочется, уменьшайте срок хранения у камеры,
а не длину чанка на рекордере.

**Бэкап.** Важна база: `docker compose exec db pg_dump -U family family_assistant`.
Кадры — расходный материал, они и так удаляются через две недели.

**Обновление.** `git pull && docker compose up -d --build`. Схема БД создаётся
автоматически; **удаление** колонок автоматически не произойдёт — когда схема начнёт
меняться всерьёз, нужен Alembic.

**Смена модели.** Поменять `LLM_*` в `.env`, `docker compose up -d`. Экран «Модель и
знания» хранит выбор семьи (локальная / облачная / гибрид) — он влияет на поведение
приватности; сам endpoint задаётся переменными окружения.

**Уведомления не приходят.** Проверять по порядку: панель открыта по HTTPS; сайт
установлен на главный экран (на iPhone это обязательно); в профиле уведомления
включены; `VAPID_*` заданы — при пустых ключах `web` пишет об этом в лог при старте.
Кнопка «Проверить» в профиле отправляет тестовое уведомление и показывает, что
именно не так.
