# Развёртывание

Две части: сервер (Docker) и домашний воркер рядом с камерами (обычный Python-процесс).

Просто посмотреть, как всё работает, проще без этого: `python run_local.py` поднимет
панель на SQLite с демо-данными и офлайн-агентом (см. README).

## Сервер

```bash
git clone <repo> && cd FamilyAssistant
cp .env.__EXAMPLE__ .env
```

Заполнить `.env`. Секреты обязательны, случайную строку удобно получить так:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

| Переменная | Зачем |
|---|---|
| `POSTGRES_PASSWORD` | пароль БД |
| `SESSION_SECRET` | подпись сессионных cookie; поменяется — все выйдут из панели |
| `INGEST_API_KEY` | им домашний воркер представляется серверу |
| `VAPID_*` | ключи для уведомлений, см. ниже |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | модель; без них панель работает, чат — нет |
| `PUBLIC_BASE_URL` | адрес панели снаружи — подставляется в ссылки-приглашения и уведомления |
| `COOKIE_SECURE` | `true` только за HTTPS |

Ключи для уведомлений генерируются один раз и кладутся в `.env`:

```bash
docker compose run --rm web python -m scripts.vapid_keys
```

Менять их потом нельзя: все подписки устройств станут недействительными, и семье
придётся заново разрешать уведомления в профиле.

Запуск и первая семья:

```bash
docker compose up -d --build
docker compose exec web python -m scripts.seed \
    --family "Наша семья" --name Марина --username marina --password ... --relation мама
```

Поднимутся `web` (панель + уведомления + ingest), `scheduler`, `db` и `redis`.
Проверить: `curl localhost:5000/healthz`.

Остальных участников глава семьи добавляет в панели; каждому достаётся одноразовая
ссылка-приглашение, по которой человек придумывает себе пароль.

### HTTPS обязателен

Не для галочки: без TLS браузер не даст ни установить приложение на телефон, ни
подписаться на уведомления — service worker работает только на HTTPS (исключение —
`localhost` для разработки). Плюс `COOKIE_SECURE=true` по простому HTTP молча
выбрасывает сессионную куку, и вход «не срабатывает» без всякой ошибки.

Ставьте панель за nginx / Caddy / Traefik с настоящим сертификатом. Caddy делает это
в две строки:

```
assistant.example.com {
    reverse_proxy localhost:5000
}
```

### Установка на телефон

* **Android (Chrome):** открыть панель → «Установить приложение» (или меню →
  «Добавить на главный экран»).
* **iPhone (Safari):** «Поделиться» → «На экран Домой». Это не косметика: до
  установки iOS вообще не отдаёт сайту push-уведомления.

Дальше в «Настройки → Профиль» человек включает уведомления и жмёт «Проверить» —
должно прийти тестовое сообщение.

### Необязательный Telegram

Если мессенджер всё-таки понадобится, у бота есть готовый профиль:

```bash
docker compose --profile telegram up -d
```

Нужен `TELEGRAM_BOT_TOKEN` от [@BotFather](https://t.me/BotFather). Бот подключается
к тому же диалогу и тем же инструментам — это просто ещё один транспорт.

## Домашний воркер

Ставится **на машине рядом с камерами**: RTSP по интернету гонять незачем, да и YOLO
должен работать там, где кадры и так есть.

```bash
pip install -r requirements-edge.txt
cp edge/cameras.yml.example edge/cameras.yml
```

В `edge/cameras.yml` — адреса камер (обычно sub-stream: он мельче и дешевле для
детекции), адрес сервера и тот же `INGEST_API_KEY`. Запуск:

```bash
python -m edge.main
```

Веса YOLO подтягиваются автоматически при первом запуске. Камера появится в панели
сама, после первого события.

### Как воркеру достучаться до сервера

Публиковать ingest в интернет необязательно и нежелательно. Варианты, от простого:

* **Приватная сеть** (Tailscale / WireGuard) — воркер видит сервер по внутреннему
  адресу, наружу не торчит ничего.
* **SSH reverse tunnel** — если сервер снаружи, а дом за NAT.
* **Публичный HTTPS** — тогда обязательно с TLS и длинным `INGEST_API_KEY`.

### Автозапуск (systemd)

```ini
[Unit]
Description=Family Assistant edge worker
After=network-online.target

[Service]
WorkingDirectory=/opt/FamilyAssistant
ExecStart=/opt/FamilyAssistant/.venv/bin/python -m edge.main
Restart=always
RestartSec=10
User=family

[Install]
WantedBy=multi-user.target
```

## Эксплуатация

**Логи.** `docker compose logs -f web scheduler`. Уровень — `LOG_LEVEL`.

**Диск.** Кадры лежат в томе `media`, ротация — по `Camera.retention_days` (14 дней по
умолчанию), делает `scheduler` ночью в 4:00. Событие в БД переживает свой снимок.

**Бэкап.** Важна база: `docker compose exec db pg_dump -U family family_assistant`.
Кадры — расходный материал, они и так удаляются через две недели.

**Обновление.** `git pull && docker compose up -d --build`. Схема БД создаётся
автоматически; **удаление** колонок автоматически не произойдёт — когда схема начнёт
меняться всерьёз, нужен Alembic.

**Смена модели.** Поменять `LLM_*` в `.env`, `docker compose up -d`. Экран «Модель и
знания» хранит выбор семьи (локальная / облачная / гибрид) — он влияет на поведение
приватности; сам endpoint задаётся переменными окружения.

**Уведомления не приходят.** Проверять по порядку: панель открыта по HTTPS; сайт
установлен на главный экран (на iPhone это обязательно); в профиле уведомления
включены; `VAPID_*` заданы — при пустых ключах `web` пишет об этом в лог при старте.
Кнопка «Проверить» в профиле отправляет тестовое уведомление и показывает, что
именно не так.
