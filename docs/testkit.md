# Стенд: как проверять панель целыми путями

Стенд — служебный ход в панель, которым **пользовательские пути проходятся
снаружи** так, как их проходит человек: сказал ассистенту, подтвердил действие,
открыл экран, дождался утренней сводки. Разница в том, что видно изнутри: в
ответ на тот же вызов приезжают трейс прогона, предупреждения сервера, снимок
базы и все обращения к модели.

Тестам он не замена. Тест знает, что проверяет, и потому не находит того, чего
не ждал; стенд ходит целыми путями и ломается там, где расходятся куски, каждый
из которых по отдельности прав.

Порядок работы для агента — [`agents/testing.md`](agents/testing.md).
Код: [`app/testkit/`](../app/testkit/) · пульт: [`scripts/testkit.py`](../scripts/testkit.py)
· сценарии: [`scenarios/`](../scenarios/).

---

## 1. Поднять стенд

```bash
pip install -r requirements.txt

export TESTKIT_TOKEN=$(python -c "import secrets; print(secrets.token_urlsafe(24))")
export TESTKIT_URL=http://127.0.0.1:8000

python run_local.py                      # панель на 8000, база в .local/
python scripts/testkit.py health         # ok: true — стенд отвечает
```

Стенд включается ключом и без него не существует: ни роутов, ни журнала
запросов, ни подмены модели. Ключ короче двадцати знаков не принимается — эти
ручки ходят мимо входа и мимо ролей.

Ключ живёт в окружении сервера **и** пульта: сервер поднимается с ним, пульт
берёт его из `TESTKIT_TOKEN`. Удобно держать в `.env` рядом с проектом.

**В бою ключ пустой.** `reset` сносит базу целиком, `login` пускает без пароля,
`state` показывает чужие строки. Стенд — для локального прогона и для отдельно
стоящей проверочной среды.

Ключа настоящей модели не нужно: без него панель работает офлайн-разбором
ключевых слов, а что «решит» модель на важном ходу, говорит сам сценарий.

## 2. Прогнать готовые сценарии

```bash
python scripts/testkit.py run scenarios/*.yaml
```

```
=== День питания (nutrition-day.yaml)
  ok  01. записал приём пищи словами
  БАГ 02. экран питания показывает записанное
       ↳ код ответа 404, ждали 200
  журнал: .local/scenarios/nutrition-day.json  ·  претензий: 1
```

Каждый сценарий начинается с `reset`, поэтому прогоны не мешают друг другу — и
поэтому же **смотреть базу после прогона нескольких сценариев бессмысленно**:
её уже снёс следующий. Разбирать надо журнал прогона либо перезапустить один
сценарий и смотреть базу сразу.

В журнале `.local/scenarios/<имя>.json` лежит всё, что было на каждом шаге:
реплика и ответ, вызванные инструменты, карточки, ждущие действия, трейс
прогона, обращения к модели, предупреждения сервера и запись о каждом запросе.

## 3. Обойти экраны

```bash
python scripts/testkit.py crawl marina     # участник
python scripts/testkit.py crawl admin      # администратор
```

Обход открывает все GET-адреса панели глазами человека и ищет не тексты, а
обвалы: пятисотку, пустой ответ, заслон не на своём месте. `403` в списке —
это чаще всего правильное разделение ролей (участнику не открывается
админский экран), поэтому строки читаются глазами, а не по счётчику.

## 4. Посмотреть, что было внутри

```bash
python scripts/testkit.py requests --bad         # запросы с ошибкой или предупреждением
python scripts/testkit.py traces --user marina   # промпты, вызовы, токены, ошибки
python scripts/testkit.py calls                  # обращения к модели, включая офлайн
python scripts/testkit.py state marina --tables meals,board_entries
python scripts/testkit.py messages               # что ассистент сказал сам
```

Предупреждение сервера — самый частый след поломки: «модель отчиталась о работе,
которой не было», «не разобрал запись на величины», «инструмент упал». Каждое
привязано к запросу, который его выписал, и к шагу сценария.

## 5. Пройти путь руками

Одиночные вызовы — когда путь ещё не оформлен сценарием:

```bash
python scripts/testkit.py reset
python scripts/testkit.py say marina "съел суп и салат" --brief
python scripts/testkit.py confirm marina                  # или --reject
python scripts/testkit.py open marina /nutrition/meal
python scripts/testkit.py post marina /memory/entries/add --data '{"board_id":1,"text":"вода 456"}'
python scripts/testkit.py tool marina set_reminder --arguments '{"text":"врач","at":"2026-12-31 09:00"}'
python scripts/testkit.py tick --at "2026-08-17 08:30:00"
```

`say` отдаёт ответ вместе с внутренностями, `open`/`post` ходят по настоящим
адресам панели с настоящей кукой входа, `tool` зовёт инструмент напрямую —
им удобно готовить состояние, — а `tick` прогоняет минуту расписаний с явным
временем, чтобы не ждать девяти утра.

## 6. Написать свой сценарий

Сценарий — файл YAML в `scenarios/`: известная база, очередь ответов модели,
шаги и проверки.

```yaml
name: День питания
user: marina
reset: {autonomy: 2}          # 0 — «всё спрашивает», 3 — «максимально сам»

model:
  chat:
    - when: "суп"
      tool: log_meal
      arguments: {text: "суп и салат"}

steps:
  - name: записал приём пищи словами
    say: "съел суп и салат"
    expect:
      tool: log_meal
      rows: [{table: meals, min: 2, contains: "суп"}]

  - name: экран показывает записанное
    open: /nutrition/meal
    expect: {status: 200, text_contains: "суп"}
```

**Шаги.** `say` (реплика, можно с `image_b64`), `open` (экран), `post`
(действие на экране, поля формы — в `data`), `confirm` (`approve` / `reject`,
чужое действие — по `pending_id`), `tool` (инструмент напрямую), `tick`
(минута расписаний), `state` (снимок). `user:` в шаге переключает, за кого
идём; `user: anon` — никем, вход и приглашение открываются без входа.
`model:` внутри шага меняет очередь ответов модели на ходу.

**Проверки** (`expect`): `reply_contains` / `reply_not_contains`, `tool`,
`no_tools`, `status`, `text_contains` / `text_not_contains`, `pending`,
`messages_contain`, `no_warnings`, и `rows` — строки в базе:
`{table, min, max, contains, user}`. Упавший ход отмечается всегда, даже без
единой проверки.

**Значения, которые рождаются по ходу** — код приглашения, номер записи:

```yaml
  - post: /settings/accounts/member
    data: {display_name: "Соня", username: "sonya"}
    capture:
      code: {table: users, where: {username: sonya}, column: invite_code}
  - post: /invite/${code}
    user: anon
    data: {password: "sonya12345", password_repeat: "sonya12345"}
```

## 7. Режиссёр модели

Живая модель для проверки поведения не годится дважды: она разная от запуска к
запуску, и самое интересное в ассистенте случается редко. Отчиталась о работе,
не вызвав инструмента. Попросила инструмент, которого нет. Прислала мусор в
аргументах. Не ответила вовсе. Дождаться такого нельзя, а поставить — можно:

```yaml
model:
  chat:
    - {when: "суп", tool: log_meal, arguments: {text: "суп и салат"}}
    - {content: "Записала. Это оценка — поправьте, если что."}
    - {error: "Модель недоступна"}
  json:
    - {when: "фото", json: {title: "Паста", kcal: 780, protein: 40, fat: 24, carbs: 95}}
```

* `when` — подстрока последней реплики человека; ответы ищутся по порядку,
  первый подошедший выигрывает. **Ответы без `when` ставьте последними**: такой
  подходит к любому ходу и закрывает собой все следующие.
* `keep` — не вынимать ответ из очереди: им отвечают на любой ход подряд.
* `tool` + `arguments` — короткая запись одного вызова; несколько — `tool_calls`.
* `error` — модель не ответила; ассистент обязан остаться живым.
* `json` — вторая очередь: оценка блюда по фото и по описанию, разбор записи
  доски на величины, фраза для сводки по задаче статистики.

Кончилась очередь — ход доигрывает то, что стояло бы и без режиссёра: живая
модель или офлайн-разбор. В `calls` у таких ходов `scripted: false`.

## 8. Если что-то не сходится

**`401` от стенда** — ключ пульта разошёлся с ключом сервера: `TESTKIT_TOKEN`
должен быть один и тот же в обоих окружениях.

**Стенд не отвечает вовсе, а панель работает** — сервер поднят без ключа либо
с ключом короче двадцати знаков; в логе старта об этом есть строка.

**Шаг ждал экран, а получил `404`** — адреса экранов складываются из модулей:
`python scripts/testkit.py routes` покажет, какие есть на самом деле.

**Ассистент вызвал не тот инструмент** — очередь ответов кончилась и ход
доиграл офлайн-разбор. Видно в `calls` по `scripted: false`.

**Проверка `rows` не находит строку** — таблица могла быть привязана не к
человеку, а к семье или к доске: `state` без `--tables` покажет все таблицы и
то, что в них попало.
