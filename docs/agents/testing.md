# Проверка панели стендом: от «проверь» до заведённой issue

Порядок работы, когда надо пройти пользовательские пути, найти поломки и
разобрать их. Ручки, пульт, формат сценария и разбор затыков — в
[`../testkit.md`](../testkit.md); здесь только ход работы.

Держите разницу между двумя вещами, потому что вся работа сводится к ней:

* **находка** — панель ведёт себя не так, как задумана авторами;
* **своё неверное ожидание** — панель задумана иначе, чем вы предположили.

Снаружи они выглядят одинаково: шаг покраснел. Разделяет их только чтение кода,
и делать это надо до issue, а не после.

## Ход

### 1. Поднять стенд

Ключ — двадцать знаков и больше, иначе стенд не включится. Сервер держите на
своём порту в фоне и оставьте его жить до конца разбора: перезапуск теряет
журнал запросов, а он вам понадобится.

```bash
export TESTKIT_TOKEN=stand-local-0123456789abcdef TESTKIT_URL=http://127.0.0.1:8099
python -m uvicorn app.main:app --port 8099          # фоном
python scripts/testkit.py health
```

Зависимости ставьте в `.venv`, если системный python пакеты не принимает.
Гасите сервер тем же способом, каким подняли, а не поиском по имени процесса:
`pkill -f uvicorn` убивает заодно и текущую оболочку.

_Готово, когда:_ `health` отдал `ok: true` и список людей стенда.

### 2. Пройти готовые пути

```bash
python scripts/testkit.py run scenarios/*.yaml
python scripts/testkit.py crawl marina
python scripts/testkit.py crawl admin
```

_Готово, когда:_ каждый сценарий из `scenarios/` прогнан, а оба обхода экранов
просмотрены глазами. `403` в обходе — обычно правильное разделение ролей, а не
поломка.

### 3. Пройти пути, которых ещё нет

Готовые сценарии проверяют то, что уже проверяли. Ценность приносит новый путь —
тот, которым человек ходит, а стенд ещё не ходил. Берите их из того, ради чего
панель написана: README, `CONTEXT.md`, экраны, которые отдают модули.

Ходите **целым путём**: сказал → подтвердил → открыл экран → дождался сводки.
Поломки живут на стыках, а не внутри кусков; путь из одного шага их не найдёт.
Что «решит» модель на трудном ходу, говорите сами — режиссёром: отчёт о
несделанном, отказ модели, мусор в аргументах, несуществующий инструмент.

_Готово, когда:_ пройдены пути хотя бы для каждого включённого модуля и для
второго участника — приватность проверяется только вторыми глазами.

### 4. Собрать подозрительное

```bash
python scripts/testkit.py requests --bad
```

Подозрительно: покрасневший шаг, предупреждение сервера, исключение со стеком,
служебное слово в тексте для человека, «готово» без строки в базе, пустой экран
там, где данные есть.

_Готово, когда:_ выписан список подозрительного — по одной строке на случай, с
номером шага и сценарием.

### 5. Дойти до причины

По каждому случаю — до строки кода, а не до симптома:

```bash
python scripts/testkit.py traces --run N      # что ушло в модель и что вернулось
python scripts/testkit.py calls               # то же, когда трейсы выключены
python scripts/testkit.py state marina        # что стало с данными
```

Дальше — чтение кода: где эта строка родилась и кто ещё её читает. Сводка,
чат и лог действий часто берут один и тот же текст, и починка в одном месте
чинит три.

_Готово, когда:_ названы файл и строка, откуда взялось поведение, и сказано,
кого ещё оно задевает.

### 6. Отделить находку от своего ожидания

Прежде чем звать поломкой — найдите место, где так **задумано**: комментарий,
ADR в `docs/adr/`, `CONTEXT.md`, сам код. Задумано — правьте сценарий под то,
как есть, и пишите в нём, почему так. Не задумано — это находка.

Ловушки, на которых это уже проверялось: экрана `/nutrition` нет, есть
`/nutrition/meal`; общие доски видны на `/memory?section=common`, а не на
`/memory`; сводки по умолчанию выключены и включаются человеком; утренняя —
в 08:30; имя файла с камеры — часть протокола рекордера, а не произвольная
строка.

_Готово, когда:_ каждый случай из списка помечен «находка» или «моё ожидание»,
и у второго исправлен сценарий.

### 7. Завести issue

По одной на находку, через GitHub MCP (см. [`issue-tracker.md`](issue-tracker.md)).
В теле: что происходит (с выводом стенда), где именно — файл и строка, почему
так вышло, как чинить, и чем подтвердится починка. Важность называйте тем, что
человек увидит, а не словом «критично».

_Готово, когда:_ у каждой находки есть номер issue.

### 8. Закрепить сценарием

Путь, на котором вылезла находка, остаётся в `scenarios/` — с проверкой,
которая покраснеет, пока не починено. Ненайденное чинить некому, а найденное и
не закреплённое возвращается.

_Готово, когда:_ `python scripts/testkit.py run scenarios/*.yaml` прогнан
целиком, и каждый красный шаг объяснён номером issue.

## Что говорить в ответе

Списком: путь → что сломано → причина → номер issue. Отдельно — что вы приняли
за поломку по своему незнанию, и что оказалось задумано: это тоже результат
прогона, и молчать о нём значит выдавать чужую работу за свою находку.
