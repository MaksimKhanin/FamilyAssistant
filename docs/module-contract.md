# Контракт модуля

Модуль — это папка `app/modules/<name>/`, которая отдаёт один объект `Module`. Ядро
собирает приложение из того, что перечислено в `ENABLED_MODULES`, и ничего не знает
про конкретные модули.

Что модуль получает бесплатно: тумблер «включено / выключено» на каждого участника,
политику автономности для своих инструментов, трейсы и лог действий, чат, уведомления
на телефоны, шину событий, каркас панели с навигацией — включая нижнюю панель на
телефоне.

## Пять файлов

```
app/modules/finance/
    __init__.py     # module = Module(...)
    models.py       # таблицы — всегда с user_id или family_id
    service.py      # доменная логика, без FastAPI и без LLM
    tools.py        # @tool-функции: то, что умеет агент
    routes.py       # экраны панели
```

### 1. Таблицы

```python
class Expense(Base):
    __tablename__ = "expenses"
    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, ForeignKey("users.id", ondelete="CASCADE"),
                     nullable=False, index=True)
    ...
```

`user_id` для личных данных, `family_id` для общих на всю семью. Третьего не дано:
таблица без того и другого — это данные, которые нельзя ни показать, ни спрятать.

### 2. Инструменты

См. [docs/agent.md](agent.md). Главное — честный `auto_from` и `ctx.subject.id`
вместо `user_id` из аргументов.

### 3. Экраны

Обычный `APIRouter`. Контекст шаблона собирает `screen_context()` — он даёт сайдбар,
шапку, аватары семьи и бейджи:

```python
context = screen_context(request, db, current, viewed,
                         title="Расходы", subtitle="Спокойный взгляд на траты")
context["expenses"] = service.list_expenses(db, viewed.id)
return render(request, "finance/expenses.html", context)
```

Экран личных данных обязан проверить `can_see_figures(current, viewed)` и показать
заглушку, если смотрит не владелец.

### 4. Объект модуля

```python
module = Module(
    name="finance",
    title="Финансы",
    description="Считает траты и подсказывает, куда уходит",
    routers=[router],
    nav_items=[
        NavItem(slug="expenses", label="Расходы", url="/finance/expenses",
                icon="chart", group="Финансы"),
    ],
    nav_items_for=screens.nav_items,   # пункты, которые завёл сам человек

    memo_hint="Что учитывать, когда речь о деньгах: на что копите, о чём не напоминать",

    event_handlers={MEAL_CONFIRMED: [_maybe_log_grocery]},
    per_user=True,
)
```

`always_on=True` — если модуль не должен иметь тумблера (как «Память»).

`memo_hint` — подсказка к памятке: о чём человеку писать в этой области. Есть
подсказка — на экране «Профиль и агент» появляется поле, и написанное доезжает до
модели там, где эта область в деле. Нет подсказки — нет и памятки: пустое поле без
объяснения человек всё равно не заполнит. Свою памятку модуль читает сам —
`instructions.memo(db, ctx.subject.id, MODULE)`, — если у него есть собственные
обращения к модели; в разговор она попадает и без этого.

`nav_items` — пункты, известные заранее и одинаковые у всех. Если пункт заводит сам
человек (табло — экран одного показателя), модуль отдаёт вместо списка функцию
`nav_items_for(db, user) -> List[NavItem]`. Её зовут на каждый переход и про того,
кто смотрит, а не про того, от чьего лица работают, — поэтому запрос за такими
пунктами обязан быть коротким.

### 5. Включить

Добавить имя в `ENABLED_MODULES` (переменная окружения или дефолт в
`app/core/config.py`). Всё: пункт появится в меню, тумблер — в матрице онбординга,
инструменты — у агента.

## Чего модуль делать не должен

* **Ходить в чужие таблицы напрямую.** Нужны данные соседнего модуля — импортируйте
  его `service`, а не его модели. Так видно, кто от кого зависит.
* **Говорить с каналом.** Никаких `push.send_to_users` и `bot.send_message` напрямую.
  Публикуйте `AGENT_MESSAGE` на шину — доставка не ваша забота.
* **Решать за пользователя.** Всё, что меняет данные или уходит наружу, проходит через
  политику автономности. Обход `registry.execute` — это обход подтверждений.
* **Держать секреты в коде.** Только переменные окружения.

## Проверка на новом модуле

Прежде чем считать модуль готовым:

- [ ] Все таблицы со скоупом; запросы фильтруют по владельцу.
- [ ] У каждого инструмента `auto_from` соответствует тому, что он делает.
- [ ] Экран личных данных прячет цифры от других участников.
- [ ] Выключенный модуль убирает свои пункты из меню и инструменты у агента
      (`policy.available_tools` — проверяется тестом).
- [ ] Тон: «оценка», а не «расчёт»; без нравоучений; без драматизма.
- [ ] Есть ли в модуле свои обращения к модели — и получают ли они памятку области.
