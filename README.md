# Семейный цифровой ассистент

AI-ассистент для одной семьи (5–6 человек) в агентском режиме: человек пишет словами,
агент сам подбирает инструменты и делает работу.

Общение — через **панель, которая ставится на телефон как приложение** (PWA): чат,
камера для фото еды и push-уведомления о том, на что стоит взглянуть. Своё
приложение и свой канал доставки — ничего, что могут отключить снаружи.

На старте два предметных модуля — **Питание** и **Безопасность** — плюс сквозная
**память**. Ядро устроено так, чтобы третий, четвёртый и десятый модуль добавлялись
без переделки: модуль — это папка с таблицами, инструментами и экранами.

```
┌─────────────────────────────────────────────────────────────┐
│  Каналы:  панель/PWA + web push  ·  расписания               │
│           (Telegram — необязательный, выключен)              │
├─────────────────────────────────────────────────────────────┤
│  Агентское ядро: LLM с function calling, реестр инструментов,│
│                  политика автономности (сам / спросит / выкл)│
├─────────────────────────────────────────────────────────────┤
│  Шина событий (in-process или Redis)                         │
├──────────────┬──────────────┬───────────────────────────────┤
│  Питание     │ Безопасность │  Знания        (+ ваш модуль) │
│  meals       │ cameras      │  boards        напоминания    │
│  activity    │ events       │  entries       табло          │
├──────────────┴──────────────┴───────────────────────────────┤
│  Общая БД (PostgreSQL), скоуп по user_id / family_id         │
└─────────────────────────────────────────────────────────────┘
        ▲                                                    │
        │ ingest API (файлы с камер)              пульт ──────┘
┌───────┴──────────────────────────────────────────────────────┐
│  Домашний рекордер: RTSP → движение → YOLO → запись видео    │
│  (отдельный проект, ставится рядом с камерами)               │
└──────────────────────────────────────────────────────────────┘
```

Подробнее: [архитектура](docs/architecture.md) · [агентское ядро](docs/agent.md) ·
[контракт модуля](docs/module-contract.md) · [развёртывание](docs/deployment.md) ·
[дизайн-система](docs/design-system.md).

## Что уже работает

**Питание.** Фото тарелки или фраза «съел суп и салат» → оценка КБЖУ → подтверждение
или правка в одно движение → баланс дня. Оценка всегда помечена как оценка: черновик
(`≈ оценка`) становится записью, только когда человек согласился, а любая правка
цифр помечает запись как скорректированную вручную. У фабричной еды — «батончик
Марс», «пицца пепперони из Додо» — состав ассистент находит в интернете и считает
по этикетке, а не на глаз, называя человеку источник; поиск необязателен и по
умолчанию выключен (`WEB_SEARCH_PROVIDER`, см. [агентское ядро](docs/agent.md)).
На «что бы мне поесть» приходит одно блюдо с цифрами, а рацион на несколько дней
собирается на экране «План питания». Понравившееся человек запоминает — словами
(«запомни рецепт») или кнопкой на карточке, — и оно ложится в **книгу рецептов**:
ассистент считает её вкусом человека и опирается на неё, когда предлагает еду
(ADR-[0010](docs/adr/0010-blyudo-v-razgovore-racion-na-ekrane.md),
[0012](docs/adr/0012-kniga-receptov-eto-otmechennye-blyuda.md)).

**Безопасность.** Дома работает рекордер: движение → YOLO → и только если в кадре
человек или машина, кадр уезжает на сервер. Там сито смотрит на время, зону и
класс объекта; спорное отправляется модели, и лишь настоящая аномалия превращается
в одно спокойное уведомление на телефоне. Всё остальное молча ложится в лог.
Параллельно рекордер шлёт непрерывную запись — она не будит никого и просто
копится в архиве, где её можно пролистать по камерам и дням.

**Знания.** Свои разделы, а в них доски — ленты записей с инструкцией ассистенту:
«Кормления», «Показания счётчиков», «Память ассистента». «Запомни, что Соня не ест
грибы» — и это всплывёт, когда агент будет предлагать ужин. Доской можно поделиться
с семьёй; всё, чем не поделились, строго личное.

**Агентский режим.** Ползунок самостоятельности (0–3) и переключатель на каждый
инструмент: *сам* / *спросит* / *выкл*. Администратор задаёт их на весь дом, а
каждый может поправить их себе — на своём экране или прямо словами: «спрашивай,
прежде чем писать на доски», «хватит переспрашивать». Личное сильнее общего;
не перебивается только *выкл*, выставленный администратором (ADR-0012). Всё, что
агент сделал, видно в ленте «Что агент делал сегодня».

**Свой ассистент у каждого.** Характер задаётся словами — «сухо и по делу»,
«неформально, с иронией», — и ассистент говорит так со всеми, о чём бы ни шла речь.
Не задали — остаётся тот, что был всегда: тепло и спокойно, как внимательный член
семьи. Это не строчка в коде, а просто ненаписанный характер.
Отдельно от него — памятки по областям: «желчного нет, гастрит, набираю вес» уходит
в разговор о еде и в оценку тарелки, «по средам приходит уборщица» — в разбор
событий дома, и никогда наоборот.

**Озвучка.** Панель читает ответ вслух — тому, кто сам включил это себе в профиле.
Чем читать, решает администратор на всю семью: голосом самого устройства (даром,
без ключей и не выпуская текст из дома) или моделью озвучки — живым голосом с
OpenAI-совместимого `/audio/speech` (`SPEECH_MODEL`, голос и скорость выбираются
на экране «Модель и знания»). Модель не настроена или не ответила — читает
устройство: тишины вместо ответа человек не получит.

**Правила.** Сказанное однажды ассистент делает всегда: «с этого момента записывай
моё состояние на доску „Самочувствие“ со временем сообщения» — и через неделю
«проснулся, чувствую себя усталым» уезжает туда само, без напоминания. Правило про
манеру речи переписывает характер, про одну доску — её инструкцию, про целую
область — памятку; всё прочее ложится записью на доску «Поведение помощника», где
его видно и откуда его можно снять руками (ADR-0011).

**Роли.** Их две, и они не пересекаются: администратор настраивает панель для всех —
учётные записи, модель и деньги, самостоятельность ассистента, камеры, трейсы, —
а ассистентом не пользуется вовсе. Участник пользуется, а из настроек трогает своё:
характер, памятки и то, о чём ассистент его спрашивает.
Одна учётная запись — одна роль, поэтому тому, кто и настраивает дом, и разговаривает
с ассистентом, нужны две учётки (ADR-0008).

**Приватность.** Цифры питания видит только их владелец. Остальные видят,
что человек сегодня что-то записал, и не видят сколько. Кадры с камер по умолчанию
не покидают дом: в облако уходит текстовое описание события, а не снимок.

## Попробовать локально

Одна команда, без Docker и без Postgres:

```bash
pip install -r requirements.txt
python run_local.py
```

Поднимет панель на `http://127.0.0.1:8000` с базой SQLite и демо-семьёй: неделя
питания, раздел знаний с досками, две камеры и ночная тревога — чтобы экраны были живыми.
Вход: `marina` / `demo12345` и `leva` / `demo12345` — участники (на втором видно,
что чужие цифры скрыты), `admin` / `demo12345` — администратор: у него нет разговора,
зато есть все настройки. Ключи для уведомлений генерируются сами,
и на `localhost` push работает по-настоящему.

**Чат работает без API-ключа.** Если модель не настроена, агент включает
офлайн-режим (`app/agent/stub.py`) — разбор ключевых слов вместо LLM. Понимает
простые фразы и честно об этом предупреждает, зато виден весь путь: выбор
инструмента, трейс, карточка, подтверждение действия. Попробуйте в чате:

```
съел суп и салат
что было ночью дома?
запомни: Соня любит блины
сколько сегодня?
```

Чтобы говорить с настоящей моделью — положите рядом `.env` с `LLM_BASE_URL`,
`LLM_API_KEY` и `LLM_MODEL`, и запускатор подхватит их сам.

```bash
python run_local.py --reset      # начать с чистой базы
python run_local.py --no-demo    # без демо-данных
python run_local.py --port 9000
```

Всё локальное хозяйство — база, медиа и сгенерированные ключи — лежит в `.local/`
и в git не попадает.

## Развёртывание

```bash
cp .env.__EXAMPLE__ .env                    # секреты + ADMIN_USERNAME / ADMIN_PASSWORD
docker compose run --rm web python -m scripts.vapid_keys   # ключи для уведомлений → в .env
docker compose up -d --build
```

Администратор создаётся сам при первом старте — из `ADMIN_*` в `.env`. Дальше всё
делается в панели на `http://localhost:5000`: **Администрирование → Учётные записи** —
завести человека, включить ему модули, выдать ссылку. Пароль каждый придумывает себе
сам по одноразовой ссылке; администратор его не задаёт и не видит.

Первым делом заведите там участника себе: под админской учёткой ассистент не
отвечает — это вход для настроек, а не для разговора.

Пароль из `.env` применяется только к пустой базе, поэтому смена пароля в панели не
откатывается при рестарте. Забыли — `ADMIN_PASSWORD_RESET=true`, перезапуск, вход,
и сразу выключить обратно.

**На телефоне:** открыть панель в браузере и добавить на главный экран
(Android — «Установить приложение», iPhone — «Поделиться» → «На экран Домой»).
Дальше в профиле включаются уведомления. Для этого нужен **HTTPS**: без него браузер
не даст ни установить приложение, ни подписаться на уведомления.

## Камеры

Рекордер — отдельный проект (YACAID), ставится **на машине рядом с камерами**, не в
Docker: RTSP-доступы намеренно не покидают дом.

```bash
pip install -r requirements-recorder.txt
cp cfg/cfg.local.yml.__EXAMPLE__ cfg/cfg.local.yml   # камеры, INGEST_API_KEY, адрес панели
python run_recorder.py
```

Камера появится в панели сама, после первого присланного файла. Подробности —
в [развёртывании](docs/deployment.md#домашний-рекордер).

## Тесты

```bash
pytest
```

Покрыты вещи, в которых ошибка стоит дорого: политика автономности, агентский цикл с
подтверждениями, сито «тревога / не тревога», подсчёты питания, ingest, память,
шифрование уведомлений, одноразовость приглашений и работа с часовыми поясами.

Отдельно от тестов есть **стенд** — служебные ручки, которыми целые
пользовательские пути проходятся снаружи: сказал ассистенту → подтвердил
действие → открыл экран → дождался утренней сводки. В ответ приходят трейсы
прогонов, предупреждения сервера и снимок базы, а что «решит» модель на этом
ходу, говорит сам сценарий, — поэтому прогон повторяем и редкие случаи
(модель отчиталась о несделанном, не ответила, попросила несуществующее)
проверяются наравне с обычными.

```bash
export TESTKIT_TOKEN=...            # без ключа стенда не существует
python scripts/testkit.py run scenarios/*.yaml
```

Подробнее — [стенд](docs/testkit.md). В бою ключ держать пустым.

## Если понадобится мессенджер

Канал — это только транспорт, ядро о нём не знает: сообщение идёт через тот же
`Agent.respond`, а уведомления рассылаются по событию `AGENT_MESSAGE` на шине.
В репозитории лежит рабочий Telegram-бот как пример — он выключен и поднимается
отдельным профилем:

```bash
docker compose --profile telegram up -d
```

Чтобы прикрутить другой мессенджер, достаточно повторить `app/channels/telegram/bot.py`
с другим SDK — трогать модули и агента не придётся.

## Откуда это выросло

Из [YACAID](https://github.com/MaksimKhanin/YACAID) — системы видеонаблюдения с
YOLO-детекцией. Здесь та же идея развёрнута в ассистента: видеонаблюдение стало одним
из модулей, а ядром — агент. Код написан заново, YACAID использовался как референс.
